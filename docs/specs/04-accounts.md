# 계정·클라우드 저장 스펙

로그인하면 진행도가 계정에 따라다녀서, 휴대폰에서 풀던 것을 PC 에서 이어서 할 수 있다.

**상태: 구현 완료 · 연결 대기** — 코드는 다 됐고 Supabase 프로젝트 값만 넣으면 켜진다.

## 왜 필요한가

지금까지 진행도는 브라우저 LocalStorage 에만 있었다. 브라우저 데이터를 지우거나 다른 기기에서 열면 레벨·업적·오답노트가 전부 사라진다. 원소를 외우는 게임인데 며칠 쌓은 오답노트가 날아가면 학습이 끊긴다.

## 정한 것 (2026-08-17, 무열 결정)

- **목적은 기기 간 이어하기** — 한 기기 안에서 계정만 나누는 방식이 아니라 클라우드에 담는다.
- **로그인 수단은 구글 로그인과 이메일 회원가입 두 가지.**
- **플레이 로그는 전체 기록을 남긴다** — 예전에는 최근 20판만 남기고 버렸다.

## 켜고 끄기

`VITE_SUPABASE_URL` 과 `VITE_SUPABASE_ANON_KEY` 두 값이 있으면 계정 기능이 켜지고, 없으면 조용히 꺼진 채 게임만 돈다. 로그인 버튼도 나오지 않는다.

빌드로 확인한 결과, 값이 없으면 Supabase 코드가 번들에서 통째로 빠진다 — 번들 449KB 에 `supabase` 문자열이 0회. 값을 넣으면 675KB(gzip 183KB)가 된다. 키 없이 클론한 사람이 무거운 코드를 받지 않는다.

anon 키는 브라우저에 실리는 공개 키다. 실제 보호는 RLS 가 한다. `service_role` 키는 프런트엔드에 넣지 않는다.

## 데이터 구조

`supabase/schema.sql` 을 SQL Editor 에 붙여 한 번 실행하면 만들어진다. 두 번 실행해도 안전하다.

| 테이블 | 내용 |
| --- | --- |
| `profiles` | auth.users 와 1:1. 가입하면 트리거가 자동으로 만든다. |
| `progress` | 사용자당 한 행. 경험치·최고기록·오답노트·업적·일일 도전과제 스냅샷. |
| `runs` | 판마다 한 행씩 쌓는다(append-only). 전체 기록. |

RLS 로 본인 데이터만 읽고 쓸 수 있게 막았다. 남의 `user_id` 로는 조회도 삽입도 되지 않는다.

`runs` 에는 `unique (user_id, client_id)` 를 걸었다. `client_id` 는 판이 끝날 때 기기에서 만드는 고유 id 라, 같은 판이 두 번 올라가도 한 번만 남는다.

## 동기화 규칙

**클라우드가 정본이다.** 규칙을 하나로 단순하게 잡았다.

1. 로그인하면 클라우드 진행도를 내려받아 로컬을 갈아 끼운다.
2. 클라우드가 비어 있으면(첫 로그인) 지금 이 기기의 진행도를 올린다.
3. 그 뒤로는 판이 끝날 때마다 진행도 스냅샷과 이번 판 기록을 올린다.
4. 업로드가 실패해도 게임은 그대로 간다 — 로컬에 이미 남아 있고, 다음 판이나 재접속 때 다시 올라간다.
5. 오프라인에서 쌓인 것은 연결이 돌아오면(`online` 이벤트) 한 번에 밀어 올린다.

**알려진 한계** — 두 기기에서 오프라인으로 각각 플레이하면 나중에 올린 쪽이 이긴다. 필드마다 다른 병합 규칙(최고기록은 max, 누적은 합)을 두는 방법도 있지만, 합을 쓰면 같은 판이 두 번 세어지는 사고가 나기 쉬워 택하지 않았다. 판 기록(`runs`)만은 고유 id 덕에 어느 기기에서 플레이했든 한 번씩만 남는다.

## 로컬 보관량

로컬 판 기록은 최근 500판까지 들고 있다. LocalStorage 는 도메인당 5MB 남짓이라 무한히 쌓으면 언젠가 저장이 막힌다. 클라우드에는 전부 남는다.

## 화면

- 상단 바에 계정 버튼 — 로그인 전에는 🔑, 로그인 후에는 👤. 올리는 중이면 파란 점, 오프라인이거나 실패했으면 노란 점이 붙는다.
- 계정 창에서 구글 로그인 / 이메일 로그인 / 회원가입 / 로그아웃, 동기화 상태와 이 기기의 판 수를 본다.
- 로그인하면 바닥글이 "진행도가 계정에 저장됩니다" 로 바뀐다.

## 남은 절차

1. 무열이 Supabase 프로젝트를 만든다 (리전은 Northeast Asia (Seoul) 권장)
2. `supabase/schema.sql` 을 SQL Editor 에서 한 번 실행한다
3. Authentication → Providers 에서 Google 을 켜고, 구글 클라우드 OAuth 클라이언트를 만들어 연결한다
4. Authentication → URL Configuration 의 Redirect URLs 에 `https://yeol200511.github.io/ATOMIC/` 를 넣는다
5. 저장소 secret 에 `VITE_SUPABASE_URL` · `VITE_SUPABASE_ANON_KEY` 를 넣는다
6. 배포 후 실제로 로그인해 기기 간 이어하기를 확인한다
